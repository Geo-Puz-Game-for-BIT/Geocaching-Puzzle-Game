## ① 打卡结果页 P04 各状态显示条件

**关键结论：P04 实装只有「成功」一态**，处理中 / 明确失败 / 结果未知**不落在 P04**，而由相机页 P03 的横幅 + 按钮承载（对应你第 17 题的 trade-off，实装成立）。

1. **成功态**：`CameraViewModel.onSuccess(checkInId)` 在收到服务端成功回执后触发——回执即 `CheckInReceipt`（`CheckInStatus.COMPLETED` + `FragmentGrant`），此时已先 `progressStore.markLandmarkCompleted(landmarkId)` 发碎片，再发 `NavigateToResult` 进入 P04。路径：`feature/camera/CameraScreen.kt:674-680`；P04 内容见 `feature/checkin/CheckInResultScreen.kt`（`CheckInResultUiState(checkInId, grantedFragmentTitle)`）。
2. **处理中态**：客户端**没有独立「处理中」页面态**。服务端 `202 PROCESSING` → `CheckInQueryResult.Processing` → `recover` 返回 `SubmitOutcome.Failed(unknownResult=true)` → UI 置 `UploadState.UNKNOWN`，提示「服务端处理中，请稍后重试」+「重试恢复」按钮。不会永久停留；网络超时由 OkHttp（connect 15s / read 30s）→ `IOException` → UNKNOWN。路径：`core/checkin/CheckInSubmitCoordinator.kt:111-126`、`data/remote/CheckInApi.kt:100-125`。
3. **明确失败态**：`checkInFailureMessage` 覆盖的错误码落在相机页 `errorMessage`：`OUT_OF_RANGE`、`LOCATION_ACCURACY_TOO_LOW`、`CHALLENGE_EXPIRED`、`IDEMPOTENCY_CONFLICT`、`PHOTO_REQUIRED`、`NOT_CONFIGURED`。路径：`CameraScreen.kt:740-752`。注意 CHALLENGE_EXPIRED / IDEMPOTENCY_CONFLICT 会先查询旧结果再决定换新尝试（`CheckInSubmitCoordinator.kt:128-152`）。
4. **结果未知态（UNKNOWN）**：进入条件为网络中断（IOException）/ 服务端 5xx / 查询故障 / 202 处理中 / 查询 NotFound（终态保证成立前按未知保护）。「先查后走」由 `submitCoordinator.submit/recover` 内部 `queryStatus(attemptId)` 触发；UI 上用户看到「结果确认中」横幅 + 仅「重试恢复」按钮（**无重拍入口**）。路径：`CameraScreen.kt:929-938`、`CheckInSubmitCoordinator.kt:103-126`。

## ② 重拍 / 取消重拍 / 保留原照

5. **重拍入口**：相机页 P03，`photoPath != null && !retaking` 时显示「重拍」OutlinedButton；启用条件 `!isCapturing && !isProcessing && !isOutcomeUnknown`。路径：`CameraScreen.kt:940-947`、`retake()` 380-392。
6. **取消重拍**：`retaking` 态显示「取消重拍」，`cancelRetake()` 只把 `retaking=false`，**保留旧照**、不删文件、不换 attemptId，回到 `PhotoPreview`。路径：`CameraScreen.kt:394-396, 964-971`。
7. **切任务继续/放弃**：存在，入口是 `PendingDraftDialog`（进相机页发现未完成草稿时弹出）：「继续上一个」=`KeepPendingDraft`→`NavigateToDraft`；「放弃并重新开始」=`DiscardPendingDraft`→`draftStore.clear()`。**UNKNOWN 草稿不可放弃**（`canDiscard=false`，只显示「继续上一个」）。路径：`CameraScreen.kt:846-872, 398-410`、`GeoTreasureNavHost.kt:94-99`。

## ④ 计数与进度（P05 拼图 + 徽标）

11. **已获碎片/已完成地标**：存 `ExplorationProgressStore`（Preferences DataStore，key `completed_landmark_ids`）；服务端成功回执后 `markLandmarkCompleted` 写入；DataStore 为唯一真源，**重启后仍在**。路径：`app/ExplorationProgressStore.kt:35-55`。
12. **计数派生**：见开头「需你改的记录」——是 `ownedFragmentIds.size`（总进度卡）与 `section.fragments.count { id in ownedFragmentIds }`（片区 x/4），`ownedFragmentIds` 由 `ownedFragmentIdsFor(completedLandmarkIds)` 从已完成地标映射 fragmentId 而来。路径：`feature/puzzle/PuzzleScreen.kt:70-74, 140-142, 225, 240`。
13. **重复成功打卡**：集合幂等 `mergeCompletedLandmark = completed + landmarkId`（Set 去重），重复打卡**计数不增加**；服务端侧用 `Idempotency-Key: attemptId` 去重。UI 上重复成功仍会进 P04 成功页，但拼图/地图计数不变。路径：`app/ExplorationProgressStore.kt:26-27`。

## ⑤ 相机页 P03

15. **快门 disabled**：`enabled = hasCameraPermission && canShoot && !isCapturing`，其中 `canShoot = gate is CheckInGateResult.Ready`——即「门控 Ready（可靠到点）才可拍」。门控数据来自 `CheckInGate.evaluate(location, landmark.point, checkInArea)`（定位样本 + 地标点 + 逐地标打卡范围）。路径：`CameraScreen.kt:112, 975, 990`、`core/checkin/CheckInGate.kt`。
16. **人脸初检失败文案**：失败提示是**具体原因**，不是「检测清晰人脸，不比对身份」这句：`FaceCheckFailureReason` 五条——`NO_FACE「未检测到人脸，请正对镜头重拍」/ FACE_TOO_SMALL「人脸过小…」/ TOO_DARK「照片过暗…」/ TOO_BLURRY「照片模糊…」/ DETECTION_FAILED「人脸检测失败，请重试」`。路径：`core/camera/FaceQualityChecker.kt:24-30`。「不比对身份」是**功能语义**（注释「只证有人参与，不做身份识别」），**不是 UI 显示文案**；若你在 UI 上统一写「检测清晰人脸，不比对身份」作为说明性提示，请与「失败时显示具体 reason」区分开，别把说明文案当错误提示。
17. **P04 非成功态由相机横幅承载**：成立。处理中/失败/未知均在相机页以 `errorMessage` / `faceCheckMessage` / `gateMessage` 红色文字 + `ActionButtons` 承载（见 ①）。
18. **权限拒绝 / 定位不合格反馈**：相机权限拒绝 → `PermissionHint`（「需要相机权限才能拍照」+「授予权限」按钮，`CameraScreen.kt:912-923`）；定位不合格 → `gateMessage` 红色文字，文案 `BlockReason`：`NO_LOCATION「等待定位…」/ LOCATION_STALE「定位已过期…」/ ACCURACY_TOO_LOW「定位精度不足（需 ≤30 米）…」/ OUT_OF_RANGE「尚未进入地标打卡范围」`。路径：`core/checkin/CheckInGate.kt:23-28`。

## ⑥ 恢复入口

19. **页面返回/重进 + 跨进程恢复**：重进相机页时 `loadLandmarkAndDraft()` 读 `draftStore.load()`——若草稿同 id 同地标则 `recoverDraft` 直接恢复（含 `requestSent`、`uploadState`、`challengeId`、`frozenLocation`）；若草稿非终态且不同 id/地标则弹 `PendingDraftDialog`。**恢复入口在相机页本身**（无全局恢复页），跨进程/强杀后需用户重新进入该地标详情→相机入口才触发。草稿经 DataStore 持久化（含 `requestSent`），重启不丢。路径：`CameraScreen.kt:172-224`、`data/repository/CheckInDraftStore.kt`。
20. **草稿续用（C-2 路由）**：`PendingDraftDialog`「继续上一个」→ `NavigateToDraft(旧landmarkId, 旧attemptId)` → NavHost 重新 `navigate(camera(旧地标,旧attemptId))` 并 `popUpTo(CAMERA){inclusive=true}`。路径：`CameraScreen.kt:255-260`、`GeoTreasureNavHost.kt:94-99`。
