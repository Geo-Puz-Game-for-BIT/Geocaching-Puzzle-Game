## C-N01 改正 attempt 与幂等恢复（P1）✅

**问题确认**：
- 原 `RemoteCheckInRepository.submitCheckIn` 每次提交都 `createChallenge(landmarkId)`（重试即换挑战码）；
- 原 `CameraScreen` 用固定 `draftId`（`dft_demo_<landmarkId>`）当幂等键，且每次提交 `getCurrentLocation()` 重取位 → 同 key 不同 body → 服务端 `request_hash` 不一致 → `409 IDEMPOTENCY_CONFLICT`。

**修复**（规则：稳定 attemptId、不可变提交、未知先查询）：
1. `LandmarkDetailViewModel.startTask()` 每次生成独立 `attemptId`（`att_<uuid>`），不再沿用固定草稿 id；
2. 新增 `core/checkin/CheckInSubmitCoordinator`：以 `attemptId` 作幂等键，请求内容（challengeId/photoId/location）由调用方**冻结后传入**，同一尝试重试不换内容；
3. `RemoteCheckInRepository` 不再在 submit 内领挑战，`createChallenge` 独立为每尝试一次；
4. 未知结果（网络中断 / 5xx 可重试）先 `queryCheckIn(landmarkId)` 查询，确认未成功才允许重试；挑战过期先查旧结果；
5. **只有收到有效 `CheckInReceipt` 才 `markLandmarkCompleted`**，失败/未知不发奖（原有「服务端确认后发奖」保留）。

**测试**：`CheckInSubmitCoordinatorTest`（新增 7 例，Repository/HTTP 可注入 fake）覆盖：成功用 attemptId 作 key、未知→查询恢复且不重复提交、未知无旧结果→Failed(unknown)、幂等冲突→恢复/失败、挑战过期→查旧结果。

## C-N02 调整挑战顺序 ✅

**问题确认**：原「压缩/初检 → 上传 → 创建 challenge」，与「可靠到点 → 签发 5 分钟挑战 → 拍摄」不符。

**修复**：
- `createChallenge` 移出 `submitCheckIn`，改为**每尝试一次**，在 `capture()` 时（门控 Ready 后、拍摄前）签发并绑定本次拍摄；
- `CheckInDraft` 增加 `challengeId` / `challengeExpiresAt`，草稿持久化该挑战，进程退出后可恢复同挑战；
- 挑战过期：`CheckInSubmitCoordinator` 先查旧结果，确认未成功返回 `ChallengeExpired(recoveredReceipt=null)`，ViewModel 换新挑战 + 重拍；已成功则恢复不重拍。
- EXIF 时间仅辅助，客户端未用 EXIF 时间作提交凭证（`capturedAt` 为应用侧拍照时刻，服务端对设备时间不绝对可信的约定见「契约差异」）。

## C-N03 门控覆盖开拍/重拍/提交 ✅

**问题确认**：`CheckInGate` 不查 `capturedAt`；`StartTask` 读旧 gate；提交重取位未复用同一门控。

**修复**：
1. 新增 `core/location/LocationFreshness`（5 秒新鲜度纯逻辑），`CheckInGate.evaluate` 增加 `now` 参数与 `LOCATION_STALE` 原因（B 组 GPS/5s 口径的客户端实现）；
2. `LandmarkDetailViewModel.startTask()` 点按时**重新取位 + 重新门控**，通过才进入相机页并生成新 attemptId；
3. `CameraViewModel` 门控覆盖**开拍/重拍/提交**：`capture()`/`retake()` 前检查 `canShoot`；提交**复用同一 `frozenLocation`**（不再重取位），无冻结定位（位置过期）则禁用并提示「定位已过期，请重新定位后重拍」；
4. 被拒绝（越界/精度不足/过期）均在界面显示原因 + 「重新定位」按钮（可恢复动作）；详情页仍可查看。

**测试**：`CheckInGateTest`（更新，新增 stale 用例）、`LocationFreshnessTest`（新增 4 例）。

## C-N04 修相机重绑与照片替换 ✅

**问题确认**：`bindCamera` 在绑定前置 `cameraBound=true` 且早退；失败/重拍不复位。

**修复**：
- `CameraXManager.bind` 增加 `onBound` 成功回调，失败时 `unbind()` 复位；`CameraViewModel.bindCamera` 仅在 `onBound` 置 `cameraBound=true`，`onError` 置 `false`，失败后可重试；
- 重拍：`retake()` 只置 `retaking=true` **不删旧照片**，新照成功才替换（`onCaptured` 里 `deletePhoto(old)`）；`cancelRetake()` 回旧预览（`retaking=false`）。

## 契约差异（需对齐）

1. **查询接口**：C 按 `GET /checkins?landmarkId=` → `{requestId, data:{checkInId,status,fragmentGrant}}` / `404→无记录` 实现；D 服务端 `app.ts` 目前**无此路由**，需 D 落地。
2. **挑战 consumed**：D 现有 `createCheckInChallenge` 仅插 TTL 行，`checkins.ts` 未消费挑战；ADR 0004 拍板「绑定 userId+landmarkId+photoId、同事务消费」仍需 D 实现。
3. **精度口径**：客户端 `MAX_CHECK_IN_ACCURACY_METERS=30f` 已改；服务端 `geo.ts` 仍 `50m`（`validateLocationAccuracy`/`isWithinRadius`/`assertWithinCheckInArea` 三处），需 D 改 30m。战争迷雾保持 50m 不混用。
4. **服务器时间**：C 侧 `capturedAt` 为设备时间，不作为绝对可信凭证；需 D 约定「服务器接收时间 / 单调间隔」核验材料。
