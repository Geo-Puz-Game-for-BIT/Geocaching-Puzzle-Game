## 1. 草稿领域模型（已在 develop 契约中，冻结）

来源：`core/model/DomainModels.kt`（develop 已合入，不再改动字段）。

| 模型 | 字段 | 说明 |
|------|------|------|
| `CheckInDraft` | id, landmarkId, localPhoto, uploadState, createdAt, updatedAt | 当前唯一打卡草稿 |
| `LocalPhotoRef` | absolutePath, mimeType, sizeBytes | 私有目录照片引用 |
| `UploadState` | EMPTY → CAPTURED → UPLOADING → UPLOADED → CONFIRMED / FAILED | 六态状态机 |
| `UploadedPhoto` | photoId, objectKey, uploadedAt | 服务端回传 |
| `SubmitCheckInRequest` | landmarkId, challengeId, photoId, location | 提交打卡（幂等 Key 走 Header） |
| `CheckInReceipt` | checkInId, status, fragmentGrant | 服务端回执 |
| `MAX_PHOTO_BYTES` | 5_242_880 | 与 D 组契约一致（JPEG ≤5MiB） |

### 1.1 草稿状态转换（冻结）

```text
EMPTY ──拍照落文件──> CAPTURED ──开始上传──> UPLOADING ──服务端收图──> UPLOADED
                                                          │
        ┌─────────────重拍/取消(删文件+清草稿)─────────────┘
        ▼                                                     │
      EMPTY <──失败重试── FAILED <──上传异常── UPLOADED ──提交打卡──> CONFIRMED(碎片已发放)
```

约束：
- **先落文件再更新草稿**（S1-C-03 已实现）；
- **确认前不删照片**（S1-C-05 验收）：重拍才删当前照片；CONFIRMED 后草稿清空、照片保留至服务端确认成功；
- 拍照确认时进行 EXIF 方向烘焙与 ≤5MiB 压缩（S1-C-04 已实现），压缩失败保留原图。

### 1.2 照片路径规则（冻结）

- 目录：`context.filesDir/checkin_photos/`（应用私有，不进相册）；
- 命名：原始拍摄 `draft_<ts>.jpg`；确认后产物 `final_draft_<ts>.jpg`（EXIF 正立 + 压缩后）；
- 草稿持久化只存绝对路径引用，不复制文件。

## 2. 拼图模型（按 ADR 0002 冻结）

- 三校区 `CampusZone { NORTH, EAST, SOUTH }`，各 2×2，共 **12 块**；
- `PuzzleFragmentDefinition(id, landmarkId, title, pieceIndex)`，`pieceIndex` ∈ **0..3**（区内索引）；
- 打卡成功 → 服务端 `FragmentGrant` → 客户端点亮对应碎片（首次 +1 / 重复 +0，`ownedFragmentIdsFor`）；
- **无拖拽摆放、无 placement 恢复**（ADR 0002），S1-C-07（3×3 拖拽）与 S1-C-08（位置保存恢复）需按 ADR 0002 重新定义或关闭。

## 3. Room 草案（S1-C-05 实现依据）

当前草稿/进度用 Preferences DataStore（S1-C-03 交付）。按任务卡要求，S1-C-05 迁移至 Room：

### 3.1 Entity

```kotlin
@Entity(tableName = "checkin_drafts")
data class CheckInDraftEntity(
    @PrimaryKey val id: String,            // draftId
    val landmarkId: String,
    val photoPath: String?,                // 对应 LocalPhotoRef.absolutePath
    val photoMime: String?,
    val photoSizeBytes: Long?,
    val uploadState: String,               // UploadState.name
    val photoId: String?,                  // 服务端回传（UPLOADED 后）
    val createdAt: Long,
    val updatedAt: Long,
)

@Entity(tableName = "owned_fragments", primaryKeys = ["fragmentId"])
data class OwnedFragmentEntity(
    val fragmentId: String,                // 12 块唯一 ID
    val landmarkId: String,
    val campusZone: String,
    val pieceIndex: Int,                   // 0..3
    val grantedAt: Long,
)
```

### 3.2 DAO

```kotlin
@Dao
interface CheckInDraftDao {
    @Query("SELECT * FROM checkin_drafts LIMIT 1")
    fun observeDraft(): Flow<CheckInDraftEntity?>

    @Query("SELECT * FROM checkin_drafts LIMIT 1")
    suspend fun loadDraft(): CheckInDraftEntity?

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsertDraft(draft: CheckInDraftEntity)

    @Query("DELETE FROM checkin_drafts")
    suspend fun clearDraft()
}

@Dao
interface OwnedFragmentDao {
    @Query("SELECT * FROM owned_fragments")
    fun observeOwned(): Flow<List<OwnedFragmentEntity>>

    // 幂等：重复回执不重复添加（对齐 S1-C-08「重复回执不重复添加」口径）
    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun grantIfAbsent(fragment: OwnedFragmentEntity): Boolean
}
```

### 3.3 Repository 接口（对齐 S1-C-05 验收状态机）

```kotlin
interface PhotoDraftRepository {
    suspend fun createDraft(landmarkId: String): CheckInDraft       // EMPTY

}
```
