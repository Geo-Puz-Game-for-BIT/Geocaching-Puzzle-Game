## 三、需真机验证的异常场景（步骤 + 预期）

> 真机验证需在 `local.properties` 配置 `CHECKIN_API_BASE_URL` 与 `CHECKIN_AUTH_TOKEN`（D 组提供本地/云地址与 demo token），并真机安装 debug APK。

| # | 场景 | 验证步骤 | 预期 |
|---|------|----------|------|
| 1 | 拒绝相机权限 | 进入相机页 → 拒绝 CAMERA 权限 | 显示「需要相机权限」+ 授予按钮；不崩溃 |
| 2 | 取消拍照 | 拍照后点「重拍」 | 删除当前照片，回到取景；草稿清为 EMPTY |
| 3 | 重拍 | 拍照 → 重拍 → 再拍 | 旧照片被删除，新照片替换；草稿 CAPTURED |
| 4 | 人脸初检失败 | 拍无脸/侧脸/过暗照片 → 确认 | 提示具体原因（无人脸/过暗/过糊），仍处 CAPTURED，可重拍，不进 FAILED |
| 5 | 断网 / 服务端不可达 | 拍照通过初检 → 确认（断网） | 进入 FAILED，显示可读错误；照片与草稿保留，可点「重试」 |
| 6 | 上传失败重试 | 断网失败后恢复网络 → 点「重试」 | 复用已传 photoId（若有），重新领 challenge 提交，成功进入结果页 |
| 7 | 后台恢复 | 拍照/上传中切后台再回前台 | 状态不丢，草稿可恢复（DataStore 持久化） |
| 8 | 杀进程草稿恢复 | 拍照（CAPTURED/FAILED）→ 杀进程 → 重进相机页 | 照片与状态恢复；FAILED 显示「上次提交失败，请重试」 |
| 9 | 重复点击确认 | 连点「确认/重试」 | 只提交一次（isProcessing 防抖 + 服务端 Idempotency-Key=草稿 id 幂等），不重复发碎片 |

## 四、幂等与防重复设计说明

- **客户端防抖**：`CameraViewModel.submitFlow()` 开头 `if (isProcessing || uploadState == CONFIRMED) return`，且提交按钮在 `isProcessing` 时禁用。
- **服务端幂等**：`POST /checkins` 使用 `Idempotency-Key`，其值固定为**草稿 id（draftId）**——同一地标同一草稿重复提交命中服务端幂等，返回 `COMPLETED` 而非重复发奖。
- **碎片发放时机**：只有收到 `CheckInReceipt` 后才 `markLandmarkCompleted`，本地拍照成功不提前发奖。
