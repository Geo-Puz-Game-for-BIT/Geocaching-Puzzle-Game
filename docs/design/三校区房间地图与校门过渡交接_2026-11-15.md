# 三校区房间地图与校门过渡交接

日期：2026-11-15
阶段：校区/校门交互规则已建模，正式矢量地图和实测校门数据待交付。本文不把当前高德底图或旧版 SVG 当作最终体验。

## 目标与当前边界

产品最终只显示北京理工大学良乡校区任务范围。用户可在“全校概况”“所在校区全图”“当前位置跟随”三种视角间切换；北、东、南校区各有独立地图画面。校门是两个校区地图之间的连接点，确认穿过门后才播放短过渡并切换房间。用户从非门边界靠近或离开时显示提示，不能因为 GPS 单点漂移误触发切换。

目前仓库的 `design/assets-manifest.json` 为空，当前地图页仍使用高德 MapView/演示 Compose 画布。正式 SVG、其地理配准、三校区边界和校门实测区域尚未给出。本轮只实现与这些素材无关的纯地理状态和视角约束；**当前 APK 尚未显示三份 AI 矢量地图，也尚未启用校门动画或学校范围拖动限制**。

## 已落地的运行规则

`CampusMapFlow.kt` 提供下列纯逻辑，使用 GCJ-02 经纬度，不依赖 SVG 或地图 SDK：

| 规则 | 当前初值 | 含义 |
|---|---:|---|
| 定位有效性 | 精度 ≤30 米、样本年龄 ≤5 秒 | 不可靠位置不切房间、不触发校门；阈值需户外复测 |
| 非门边界预警 | 距当前校区边界 ≤25 米 | 进入已配置门区/通行廊道时不误报 |
| 过门确认 | 目标侧门区连续 2 个采样时间不同的可靠定位点 | 先进入当前侧门区，再经过门的廊道，到目标侧后切换；重复回调不算第二点 |
| 门廊道有效期 | 120 秒 | 超时或离开廊道会取消候选门，避免绕路越界被当作过门 |
| 初始视角 | 全校概况 | 无可靠当前位置时不能切换到跟随或所在校区全图 |

状态机只发出 `CampusDoorTransition(from, to, doorId)` 事件；动画由未来矢量地图 UI 消费。同一个门可从两侧进入；没有配置目标校区门区的普通出校门不能假装连接另一间房。用户在校外或两个校区之间时，保持最后一个有效校区的地图，画布不显示校外底图或真实校外位置；以提示说明当前不在可探索校区内。

`clampViewport` 以学校/校区边界的包围盒限制相机中心和可见米制范围。它是第一道拖动/缩放约束；不规则校界的包围盒仍包含校外空白，因此正式渲染器还必须按多边形裁切 SVG 和标记层，并在可视范围大于地图时使用留白。SVG 源文件本身也不能包含校外道路、建筑、地名或地图瓦片。

## 三种视角的交互

| 模式 | 画面和手势 | 与校门/定位的关系 |
|---|---|---|
| 全校概况 | 显示三校区的校内轮廓与已发现进度；相机限制在学校总轮廓 | 点击校区可进入该校区全图；过门后概况模式可保持 |
| 所在校区全图 | 完整展示当前校区，边界外留白/遮罩；地图标记只显示该校区 | 过门确认后切换到目标校区全图 |
| 跟随用户 | 用户定位居中，固定适当缩放；手动拖动后退出跟随，变为校区全图 | 过门确认后跟随目标校区；定位失效时停止相机追踪、提示恢复 |

三种模式建议使用紧凑分段控件；“回到当前位置”用定位图标。缩放按钮和双指缩放只影响当前允许边界，不能露出校外图层。画布、标记和迷雾均使用相同的地理配准，不得各自按屏幕像素猜位置。

## 校门过渡

每个逻辑门至少需要：稳定 `doorId`、连接的两校区、两侧各一个实测入口多边形、连接两侧的通行廊道多边形、门名与矢量标识。数据顺序不代表单行方向。连续可靠定位从 A 侧门区进入、沿廊道移动并在 B 侧门区确认后，才发切换事件；在门口停留、折返或 GPS 漂移不切换。若用户从非门边界离开，保留当前地图并提示返回门或重新定位，不能自动“传送”到其他校区。

动画应服务方向感：建议 250–350 毫秒的旧校区淡出/校门标识短暂居中/新校区淡入，保留门名与目标校区名。支持系统减少动态效果时直接切换或极短淡入；不使用眩晕式缩放、黑屏加载或长过场。动画期间可继续接收定位，但只在状态机确认的事件后改变房间。素材尚未交付，因此本轮不生成伪门动画。

## A/B/D/E 交付分工

| 负责人 | 需交付给集成的具体材料 | 验收要点 |
|---|---|---|
| A：视觉/矢量地图 | 全校概况 + 北/东/南三份可编辑 SVG；四图同一风格，校外图层已删除；每图 `viewBox`、方向、校区名、门标识、无字/文字层；动画静帧或动效时序 | 放大后仍是矢量；校门与道路相接；移动端缩小后道路/地标可辨；不得把官方 PDF 像素当 GPS |
| B：地理数据与 Android | GCJ-02 学校总轮廓、三校区互不含糊的多边形；每门两侧入口和通行廊道；SVG 地理控制点；接入专用矢量渲染器、三模式控件、边界遮罩与状态事件 | 每个门 ID 稳定；校门两侧真实可通行；相机、迷雾、标记、人物共用投影；定位抖动不切区 |
| D：后端/配置 | 若地图/门配置要由服务端下发，提供版本号、原子发布、旧版兼容和离线缓存契约；否则当前可先随 APK 静态打包 | 不把尚未核验的门/边界标为正式；不会因服务端暂不可达而显示校外底图 |
| E：测试与集成 | 两台设备逐门步行、折返、非门越界、弱定位、拖动/双指缩放、横竖屏、减少动态效果和断网证据 | 带提交 SHA、配置/资产版本、门 ID、GPS 精度、截图/录屏、预期/实际；检查全程没有校外像素/标签 |

A 的绘画工作优先交付矢量源文件，不必为绘图额外生成 Android 代码。B 在收到可用 SVG 后负责导入和投影。校门和校界数据须由 B 与 A 对照现场、学校官方图和矢量画面确认；不能从当前 12 个地标的包围盒或有问题的旧 SVG 自动推算。

## 矢量资产与地理配准契约

1. 四份 SVG 使用稳定资源键（例如 `school-overview`、`north`、`east`、`south`），资源键由 B 最终映射到文件；不把文件名硬编码进定位算法。
2. 每图提供至少 3 个非共线、推荐 4 个以上的 GCJ-02 控制点及对应 SVG `viewBox` 内的 `(x,y)`；标明点的现场依据、采集日期和误差。B 计算投影并记录残差，残差过大先修图或控制点，不靠放宽打卡范围掩盖偏移。
3. 提供与 SVG 对应的学校/校区闭合边界多边形。学校轮廓、校区轮廓、门区和廊道都使用同一坐标系；每个校区内的地标坐标和迷雾分块必须可落在同一投影上。
4. SVG 不含校外内容；渲染层仍按校界裁切所有图层。概况与分区切换不能瞬间闪出未经裁切的底图。
5. Asset manifest 记录版本、SHA-256、`viewBox`、控制点、边界版本和门数据版本；失配时阻止启用专用矢量地图并给出明确错误，不静默回退到可查看校外的高德底图。

## 验收矩阵

- 从全校概况进入三个校区全图，再切到跟随用户；返回上级或重新居中都不丢当前校区。
- 每条门从两侧各走一次；门口徘徊/折返不触发，真正到达另一侧后只触发一次短动画。
- 沿非门边界走近出现提醒，继续走出仍保持原房间地图；弱 GPS、旧定位、单点跳变不触发过门。
- 在全部模式下持续拖拽、惯性滑动、双指缩小到极限；截图/像素检查没有校外图层、地名或瓦片，人物点不会被画到校外画布。
- 缺 SVG、控制点、校界或门数据时不宣布该功能已完成；当前纯规则单测只是逻辑前置验证。
