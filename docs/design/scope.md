## 1. 一句话范围

> 一名玩家，用一个账号，跑完**一个片区模块**：在 4 个典型地标各完成 1 次拍照打卡，
> 拿到 **4 块碎片**，拼成这个片区的 **2×2 模块**；三个这样的模块拼起来，就是一张完整校园地图。
> **P0 演示只跑通「南校区 MP-A」这一个模块**（另两个模块结构与数据同构，P1 开放）—— 这个闭环跑通即 P0 达标。

## 2. 四个锚点（验收就查这四条）

### 锚点 1：一个账号

- **登录方式**：单账号演示态。手机号 + 验证码走通真实链路，但演示只用一个固定账号 `138****0001`；
  同时支持"游客预览"进入地图（只读，不能打卡）。
- **账号态**：登录态存本地（DataStore），冷启动自动恢复；退出登录只清本地，不调服务端注销。
- **账号内数据**：昵称、头像（可不上传，用默认字母头像）、当前进度（各片区已得碎片数、已合成模块数、已解锁成就）。
- **不做**：注册、找回密码、第三方登录、多设备同步、账号注销、头像上传裁剪（用默认头像）。

### 锚点 2：一个片区模块（4 个典型地标）

地图 = **3 个片区模块**，一个模块 = **4 个地标**，这是拼图的最小完整单元。

| 模块 | 名称 | 含地标（P0 只做 MP-A） | 状态 |
|---|---|---|---|
| `MP-A` | 南校区 | `LM-001` 疏桐 · `LM-002` 博雅 · `LM-003` 理教 · `LM-004` 工业生态楼 | **P0 实现** |
| `MP-B` | 北校区 | 北湖 · 综教 · 学服 · 图书馆 | P1（原型显示 1/4 占位） |
| `MP-C` | 东校区 | 甘棠 · 勤园 · 文萃 · 文博中心 | P1（原型显示 0/4 占位） |

- **地标字段（最小集）**：`id`、`名称`、`一句话介绍`、`封面图`、`难度（1–3 星）`、
  `地形`、`允许打卡半径 R=30m`、`状态（未打卡 / 已打卡）`、`moduleId`、`关联任务 id`。
- **展示位**：P01 地图页 Marker + 底部卡片；P02 详情页全量展开。
- **不做**：地标搜索、分类筛选、收藏、评论打分、跨片区导航、地标列表分页。

### 锚点 3：一个任务（每个地标一个拍照任务）

- **任务**：`T-001 林口留影` —— 在疏桐林口 **30m 半径内**拍一张照片并提交，
  校验通过后发放 **该地标的 1 块碎片**（碎片与地标一一对应，`LM-001 → MP-A 第 1 格`）。
- **四个任务一一对应四个地标**：`T-001 林口留影`（疏桐）· `T-002 廊下小坐`（博雅）·
  `T-003 台阶留影`（理教）· `T-004 楼前合影`（工业生态楼）。
- **任务字段**：`id`、`类型=拍照打卡`、`标题`、`玩法说明`、`目标地标`、`半径`、
  `状态（未开始 / 进行中 / 待校验 / 成功 / 失败）`、`奖励（模块 id + 格位 index）`、`提示 hint`。
- **校验规则（P0 版）**：
  1. 距离：打卡点与目标点 ≤ 30m；
  2. 定位精度：`accuracy ≤ 20m`，否则提示等待；
  3. 照片：非空、≤ 1280px 最长边、EXIF 时间在提交前后 5 分钟内。
- **不做**：多任务并行、任务链、限时挑战、队伍协作、AR 识别、图文混合提交。

### 锚点 4：2×2 模块拼图闭环（4 块 → 模块，3 模块 → 地图）

- **碎片**：一格 = **一个地标的一张打卡照**，四格 = 一个 2×2 模块；三个模块 = 12 格 = 完整校园地图 `MAP-001`。
- **获得**：在地标打卡成功 → 该地标对应的那一格亮起。
  P0 演示脚本：`MP-A` **预置 3 块**（博雅 / 理教 / 工业生态楼），现场到疏桐打第 4 块，制造"最后一击"。
- **两级交互**：
  1. **P05 地图总览**——三个片区并排，已合成的灰金边框 + `已合成`，未集齐的显示 `n / 4` 与灰锁；
  2. **P05 片区拼图**——点进片区看 2×2 大格，已得高亮并带地名，未得灰锁；点两块可互换位置，落位正确吸附。
- **完成（两级奖励）**：
  - 4 块集齐 → 合成该片区 → 发成就 `成就 · 拼合南校区`，地图进度 `1 / 3`；
  - 3 个模块全部合成 → 发成就 `成就 · 校园地图完成`，`12 / 12`，金框 + 完整地图。
  - P0 用 Compose 属性动画，不用 Rive。
- **不做**：多张地图、碎片交易、拼图分享图生成、拖拽之外的旋转/缩放玩法、片区顺序自定义。

## 3. 五页边界（本次原型只做这五页）

| 编号 | 页面 | 必须承载 |
|---|---|---|
| P01 | 地图 | 我的位置、4 个地标 Marker + 卡片、定位中/失败/离线态 |
| P02 | 地标详情 | 名称、介绍、距离、难度、任务说明、去打卡入口 |
| P03 | 相机打卡 | 取景、拍摄、重拍、提交、进度反馈 |
| P04 | 结果 | 成功（得碎片 `n/4`、去拼合片区）/ 失败（原因 + 下一步） |
| P05 | 拼图 | **两级视图**：地图总览（3 片区 × `n/4`）⇄ 片区 2×2（4 格拖拽归位、集齐合成） |

> 与 SRS 第 5 章 P01–P06 的差异：**P0 砍掉"探索列表 P02 原编号"与"个人中心 P06"**，
> 五页就能闭环。P06 个人中心降级为"我的"浮层入口（只放昵称 + 进度 + 退出），不单独成页。
> P05 的两级视图仍是**一页**，用页内切换承载，不额外增页。

## 4. 失败恢复矩阵（验收必查）

| # | 场景 | 触发条件 | 界面反馈 | 恢复动作 | 落地页 |
|---|---|---|---|---|---|
| F1 | 定位权限被拒 | 首次进入 P01 拒绝授权 | 顶部横幅「需要位置权限才能找到附近地标」+ 去设置 | 去设置 → 返回自动重新请求 | P01 |
| F2 | 相机权限被拒 | P03 拒绝授权 | 全屏空态「需要相机权限才能拍照打卡」+ 去设置 | 同上 | P03 |
| F3 | 定位精度不足 | `accuracy > 20m` | 卡片提示「定位还不够准（±45m），等一等或到开阔处」+ 重试 | 自动重试 3 次，手动重试 | P01/P03 |
| F4 | 超出打卡半径 | 距离 > 30m | 「还差 68 米，再走近一点」+ 显示实时距离 | 导航箭头引导，距离进入半径后按钮自动可用 | P03 |
| F5 | 弱网 / 断网 | 无网络 | 顶部离线条「离线中，打卡会存草稿」；可提交 | 存本地草稿，标「未同步」 | P01/P03/P05 |
| F6 | 提交失败 | 上传超时 / 5xx | 「没提交成功，已存草稿」+ 重试按钮 | 手动重试，恢复网络后自动补传 | P03/P04 |
| F7 | 照片校验失败 | 照片为空 / 过大 / EXIF 超时 | 「这张照片用不了：拍摄时间超出 5 分钟，重新拍一张」 | 一键重拍（≤3 步） | P03/P04 |
| F8 | **片区内碎片未集齐** | 模块内碎片 < 4 | 灰锁格 + 「还差 2 块，去地图找对应的地标打卡」；列出 4 个地标的打卡状态 | 跳回 P01 或直接点清单里的地标 | P05 |
| F9 | 重复打卡 | 同一地标已成功过 | 「你已经打过卡了」+ 查看拼图 | 跳 P05 对应片区 | P02/P03 |
| F10 | 冷启动加载 | 首屏数据未到 | 骨架屏（卡片占位），不超过 3 秒 | 超时给"重新加载" | P01/P02/P05 |
| **F11** | **片区未开放** | 点 `MP-B` / `MP-C` | 格位为灰锁占位，进片区提示「这个片区下一版开放」，已合成部分照常可见 | 退回地图总览，不阻塞 | P05 |

**统一文案口径**：错误提示 = 「发生了什么 + 现在能做什么」，不出现 HTTP 状态码、异常类名。
**统一恢复原则**：任何错误页至少留一个可行动作（重试 / 重拍 / 去设置 / 返回），不做死路。
**新增规则（v1.1）**：碎片与地标**绑定**，跨片区碎片不可互换；未获得的格子不暴露内容（灰锁），避免提前剧透。

## 6. 数据锚点（与后端契约的最小字段）

```
Map      { id, name, moduleIds:["MP-A","MP-B","MP-C"], completedModules, totalTiles:12 }
Module   { id:"MP-A", name:"南校区", order:1, landmarkIds:[4], grid:2, tiles:[{index,landmarkId,owned,placed}] }
Landmark { id, moduleId, name, intro, coverUrl, difficulty:1-3, terrain, lat, lng, radius:30, status }
Task     { id, landmarkId, type:"PHOTO", title, howTo, hint, reward:{ moduleId, tileIndex } }
Checkin  { id, taskId, userId, photoUrl, lat, lng, accuracy, capturedAt, state, failReason }
User     { id, nickname, avatarSeed, progress:{ "MP-A":3,"MP-B":0,"MP-C":0 }, modulesDone, achievements[] }
```

- `grid` 固定为 `2`（一个模块 2×2），`tileIndex = 行*2 + 列`，取值 `0–3`。
- 碎片与地标绑定：`tiles[i].landmarkId` 决定这一格显示哪张打卡照，**不做跨片区换片**。
- `state` 取值：`PENDING / SYNCING / SUCCESS / FAILED / DRAFT`。
- `failReason` 取值：`OUT_OF_RADIUS / LOW_ACCURACY / PHOTO_INVALID / NETWORK / DUPLICATE / MODULE_LOCKED`。

## 7. 不做清单（P0 明确排除）

- 多账号 / 注册 / 找回密码 / 第三方登录 / 好友与社交 / 排行榜 / 队伍
- 任务链、限时挑战、多任务并行、AR 识别、图文混合提交
- 多张地图、碎片交易、拼图分享图、旋转缩放玩法、片区顺序自定义
- `MP-B` / `MP-C` 的打卡内容（P0 只保留结构与占位）
- Rive / Lottie 动效（用 Compose 属性动画替代）
- 埋点后台、运营配置、消息推送、客服与举报

> 变更流程：要加任何一条，先在本文档追加一行到"已解冻"小节并写明代价（工期 + 风险），组内确认后再动。
