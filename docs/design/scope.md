## 1. 一句话范围

> 一名玩家，用一个账号，跑完**一个片区模块**：在 4 个典型地标各完成 1 次拍照打卡，
> 拿到 **4 块碎片**，拼成这个片区的 **2×2 模块**；三个这样的模块拼起来，就是一张完整校园地图。
> **三个片区（南 / 北 / 东）结构同构、数据齐备，共 12 块** —— 本次演示仍跑通「南校区 MP-A」这条闭环。

### 1.1 关于「只有南区有连线」（原型限制，不是范围限制）

| 事实 | 说明 |
|---|---|
| 原型（HTML / Figma）里只有 `MP-A` 有完整的 P01→P02→P03→P04→P05 连线 | **原型连线覆盖度的限制**：一条闭环做全交互；另两片区的页面结构与数据完全同构，靠顶部校区切换器（北 / 南 / 东）直接查看 |
| 北校区、东校区在原型里可切换、可看进度、可看 2×2 | 是。**不是「下一版开放」**，也不是灰锁占位 |
| 旧的「F11 片区未开放 / 这个片区下一版开放」 | **已作废**，从 v1.3 起删除。原型 P05 里已无此文案 |

> 若需要北 / 东的完整连线，是**原型工作量**问题，不是范围问题；需要的话我照南区同构补，
> 交互与文案不用重新设计。

## 2. 四个锚点（验收就查这四条）

### 锚点 1：一个账号

| 条目 | 内容 | 状态 |
|---|---|---|
| 演示账号 | 单账号演示态，固定账号 `138****0001`；同时支持游客预览（只读，不能打卡） | 已确认 |
| **登录方式** | 手机号 + 验证码走真实链路 | **候选** —— 是否保留验证码、是否改用校内统一身份，等 E 拍板 |
| 账号态 | 登录态存本地（DataStore），冷启动自动恢复；退出只清本地，不调服务端注销 | 已确认 |
| 账号内数据 | 昵称、头像（默认字母头像，不上传裁剪）、各片区进度、已合成模块数、成就 | 已确认 |

- **不做**：注册、找回密码、第三方登录、多设备同步、账号注销、头像上传裁剪。

### 锚点 2：三个片区模块（每个 4 个地标）

地图 = **3 个片区模块**，一个模块 = **4 个地标** = **2×2 四块碎片**。**三个片区都在此次范围内。**

| 模块 | 名称 | 含地标 | 状态 |
|---|---|---|---|
| `MP-A` | 南校区 | `LM-001` 疏桐 · `LM-002` 博雅 · `LM-003` 理教 · `LM-004` 工业生态楼 | 已确认（演示闭环在此） |
| `MP-B` | 北校区 | `LM-005` 北湖 · `LM-006` 综教 · `LM-007` 学服 · `LM-008` 图书馆 | 已确认（同构） |
| `MP-C` | 东校区 | `LM-009` 甘棠 · `LM-010` 勤园 · `LM-011` 文萃 · `LM-012` 文博中心 | 已确认（同构） |

- **地标字段（最小集）**：`id`、`名称`、`一句话介绍`、`封面图`、`难度（1–3 星）`、
  `地形`、`状态（未打卡 / 已打卡）`、`moduleId`、`关联任务 id`。
  **打卡半径已从地标字段里移除**（原 `radius:30`），改由**服务端规则**判定，客户端不写死。
- **展示位**：P01 地图页 4 个 Marker + 底部推荐卡片；P02 详情页全量展开。
- **不做**：地标搜索、分类筛选、收藏、评论打分、跨片区导航、地标列表分页。

### 锚点 3：一个任务（每个地标一个拍照任务）

- **任务**：拍一张**人物与目标地标同框**的照片并提交；服务端确认后发放该地标对应的 1 块碎片
  （碎片与地标一一对应，例：`LM-001 疏桐 → MP-A 第 1 格`）。
- **任务字段**：`id`、`类型=拍照打卡`、`标题`、`玩法说明`、`目标地标`、
  `状态（未开始 / 进行中 / 待确认 / 成功 / 未成功）`、`奖励（模块 id + 格位 index）`、`提示 hint`。
- **判定规则（三项均为候选，客户端不写死）**：

| # | 项 | v1.2 写法 | v1.3 状态 | 界面上怎么写 |
|---|---|---|---|---|
| 1 | 打卡半径 | `≤ 30 m` | **候选** | 「需要到达地标附近」 |
| 2 | 定位精度 | `accuracy ≤ 20 m` | **候选** | 「定位要能用」，显示实时定位误差作为**技术观察**，不写成门槛 |
| 3 | 照片时效 | EXIF 时间在提交前后 5 分钟内 | **候选** | 「照片需现场拍摄」 |
| 4 | 照片内容核验 | 不做人脸 / 身份识别 | 已确认 | 「只需要人和地标同框，不做人脸识别，也不要身份认证」 |

> 关于「定位误差约 30 m」：这是**现场技术观察值**，用来说明为什么精度不稳，
> **不等于打卡半径**。原型地图上已删除圆形可打卡范围，界面上不再出现固定的米数圈。

- **不做**：多任务并行、任务链、限时挑战、队伍协作、AR 识别、图文混合提交、
  **人脸识别 / 身份认证**。

### 锚点 4：2×2 模块拼图闭环（4 块 → 模块，3 模块 → 地图）

- **碎片**：一格 = **一个地标的一张打卡照**，四格 = 一个 2×2 模块；三个模块 = 12 格 = 完整校园地图 `MAP-001`。
- **获得方式（v1.3 修正）**：服务端确认打卡成功 → 该地标对应的那一格**自动点亮、自动归位**。
  **不需要拖拽，也没有拖拽门槛**。手动「回顾拼合过程」只是集齐后的**次级入口**，不占主按钮。
- **两级交互**：
  1. **P05 地图总览**——三个片区并排，已集齐的显示「已合成」，未集齐的显示 `n / 4`；
  2. **P05 片区 2×2**——点进片区看四格，已得显示校园地图图案与地名，未得显示暗灰绿空格并保留边界；
     点已点亮的格子可查看它的地标与打卡记录。
- **完成（两级奖励）**：
  - 4 块集齐 → 合成该片区 → `成就 · 拼合<片区名>`，地图进度 `n / 3`；
  - 3 个模块全部合成 → `成就 · 校园地图完成`，`12 / 12`。
  - P0 用 Compose 属性动画，不用 Rive。
- **演示脚本（数据自洽口径）**：

| 阶段 | 南校区 MP-A | 北校区 MP-B | 东校区 MP-C | 已收碎片 | 完成片区 |
|---|---|---|---|---|---|
| 打卡前（P05 `progress`） | `3 / 4`，**待获 = 疏桐** | `1 / 4` | `0 / 4` | **4 / 12** | `0 / 3` |
| 打卡后（P05 `overview`） | `已合成`（疏桐补齐） | `1 / 4` | `0 / 4` | **5 / 12** | `1 / 3` |
| 全点亮（P05 `mapdone`） | 已合成 | 已合成 | 已合成 | `12 / 12` | `3 / 3` |

> **总碎片数恒等于三片区之和**，由代码求和得出，不手写。
> 南校区「待获 = 疏桐」是演示脚本的定案：预置博雅 / 理教 / 工业生态楼三块，现场打疏桐第 4 块，
> 制造「最后一击」。P05 片区页与 P01 地图上未得的那格/那个针都是**疏桐**，两处一致。

- **不做**：多张地图、碎片交易、拼图分享图生成、拖拽/旋转/缩放玩法、片区顺序自定义。

## 4. 失败与恢复矩阵（验收必查）

| # | 场景 | 触发条件 | 界面反馈 | 恢复动作 | 落地页 |
|---|---|---|---|---|---|
| F1 | 定位权限被拒 | 首次进入 P01 拒绝授权 | 顶部横幅「需要位置权限才能找到附近地标」+ 去设置 | 去设置 → 返回自动重新请求 | P01 |
| F2 | 相机权限被拒 | P03 拒绝授权 | 全屏空态「需要相机权限才能拍照打卡」+ 去设置 | 同上 | P03 |
| F3 | 定位不佳 | 拿不到可用定位 | 「定位还不够稳」，说明是信号问题不是玩家问题 | 「等定位稳定」+ 自动重试 | P01 / P03 |
| F4 | 不在地标附近 | 距离地标尚远 | 「还没到地标附近」+ 实时距离 | 走近后按钮自动可用；不显示固定米数圈 | P03 |
| **F5** | **网络中断** | 无网络 | 「网络中断，暂时拿不到数据」+ 重试 | 恢复网络后重试；**不承诺离线补交** | P01 / P02 / P03 |
| **F6** | **提交失败** | 上传超时 / 5xx | 「没提交成功，碎片还没有发放」+ 重试 / 返回 | **照片保留在本地**，用**同一条打卡请求**重试，不重新拍 | P03 / P04 |
| F7 | 照片不可用 | 非现场拍摄 | 「这张照片用不了」，拍摄时**只检测清晰人脸，不比对身份** | 一键重拍 | P03 / P04 |
| F8 | 片区内碎片未集齐 | 模块内碎片 < 4 | 「还差 N 块：<地标名>」+ 4 个地标打卡状态清单 | 跳回 P01 或直接点清单里的地标 | P05 |
| F9 | 重复打卡 | 同一地标已成功过 | 「该地标已完成，不会重复发放碎片」+ 查看拼图 | 跳 P05 对应片区 | P02 / P03 |
| F10 | 冷启动加载 | 首屏数据未到 | 骨架屏 ≤3 秒 | 超时给「重新加载」 | P01 / P02 / P05 |
| **F11** | **结果未知（处理中 / 待确认）** | 服务端还没给出结论 | 「服务端正在确认」→「结果待确认」；**明确这一步没有结果** | **保留照片**，用原幂等请求查询；确认前**不加奖**；可从 P06「1 条打卡还在确认」回到这一条 | P04 / P06 |
| ~~F11 旧~~ | ~~片区未开放~~ | — | **v1.3 删除**：北 / 东片区同构可用，不存在「下一版开放」 | — | — |

**统一文案口径**：错误提示 = 「发生了什么 + 现在能做什么」，不出现 HTTP 状态码、异常类名。
**统一恢复原则**：任何错误页至少留一个可行动作（重试 / 重拍 / 去设置 / 返回），不做死路。
**新增规则（v1.3）**：

1. **不提前宣布成功** —— 处理中与待确认两态都不显示「成功」、不发碎片。
2. **幂等** —— 同一条打卡请求重复查询 / 重试，服务端只记一次，不重复发放。
3. **照片与奖励解耦** —— 删除照片**不影响**已获得的碎片和打卡记录（P06 删除确认弹窗里明写）。
4. **结果未知时照片必须留着** —— 不允许出现「拍了照、网断了、照片没了」。
5. **不做每日重置** —— 已完成的地标是「已完成」，不是「今天打过了，明天再来」。

**提交状态四态口径（v1.8，PR#8 整改）**——界面上任何打卡提交，必须能明确落到下面四态之一，
不允许把「未知」伪装成「失败」或「成功」：

| 状态 | 判定 | 界面表现 | 允许的动作 |
|---|---|---|---|
| 未发送 | 用户还没按提交（拍照后停在预览 / 草稿） | 预览页正常展示，无提交进度 | 重拍 / 提交 / 返回 |
| 处理中 | 请求已发出、服务端还没给结论 | 「正在提交打卡」遮罩，明示别退出 | 等待；退出后到 P06 可回看 |
| 明确失败 | 服务端返回拒绝（距离 / 照片 / 精度 / 重复等） | 对应失败页，说明原因与下一步 | 按失败页出口重试 |
| 结果未知 | 回执丢失（断网 / 超时 / 杀进程），请求已发出但没拿到结论 | 不显示「确定失败」；P06 出现「1 条打卡还在确认」入口 | **保留原尝试**，用同一条幂等请求查询恢复；恢复前不放开重拍、不提前授奖 |

> 「结果未知」是 PR#8 明确要求的边界：已发送但回执丢失时，**既不能直接显示确定失败，
> 也不能放开重拍或提前授奖**——只能保留原尝试并查询恢复。Android 侧
> `DemoGeoTreasureRepository.submitCheckIn` 已按此实现（提交前先查 Room PENDING 留痕）。

## 6. 数据锚点（与后端契约的最小字段）

```
Map      { id, name, moduleIds:["MP-A","MP-B","MP-C"], completedModules, totalTiles:12 }
Module   { id:"MP-A", name:"南校区", order:1, landmarkIds:[4], grid:2,
           tiles:[{index,landmarkId,owned,placed}] }
Landmark { id, moduleId, name, intro, coverUrl, difficulty:1-3, terrain, lat, lng, status }
Task     { id, landmarkId, type:"PHOTO", title, howTo, hint, reward:{ moduleId, tileIndex } }
Checkin  { id, taskId, userId, photoUrl, lat, lng, accuracy, capturedAt, requestId, state, failReason }
User     { id, nickname, avatarSeed, progress:{ "MP-A":3,"MP-B":1,"MP-C":0 }, modulesDone, achievements[] }
```

**v1.3 相对 v1.2 的字段变化**

| 变化 | 说明 |
|---|---|
| `Landmark.radius` **删除** | 半径是服务端规则，不再是地标字段 |
| `Checkin.requestId` **新增** | 幂等键：同一条打卡请求重试 / 查询结果都用它，服务端只记一次 |
| `Checkin.state` 取值调整 | `DRAFT / PENDING / CONFIRMING / SUCCESS / FAILED`；**去掉 `SYNCING` 的「自动补传」语义** |
| `failReason` 调整 | `OUT_OF_RADIUS / LOW_ACCURACY / PHOTO_INVALID / NETWORK / DUPLICATE`；**去掉 `MODULE_LOCKED`**（不再有未开放片区） |

- `grid` 固定为 `2`（一个模块 2×2），`tileIndex = 行*2 + 列`，取值 `0–3`。
- 碎片与地标绑定：`tiles[i].landmarkId` 决定这一格显示哪张打卡照，**不做跨片区换片**。
- **放置是服务端行为**：`placed` 由服务端确认后置真，客户端不再有「拖拽归位」这一态。

### 8.5 清单字段的口径（纠正「已确认来源 ≠ 文件已交付」）

### 10.3 云层迷雾 · 两级解锁（已确认）

| 级别 | 触发条件 | 表现 | 时长 |
|---|---|---|---|
| 初始 | 未打卡 | 三个校区整片被云覆盖（右下不纳入区域不画云） | — |
| **第一级 · 地标级** | 打卡成功 1 个地标（如疏桐） | 该地标头顶开一个孔洞（半径 62px，边缘 38% 柔化），孔内露出云下 3D 地图；其余 11 片云仍在 | 1.9s |
| **第二级 · 校区级** | 一个校区 4 个地标集齐（南：疏桐·博雅·工业生态楼·理教） | **该校区剩下的云整片上浮 + 淡出**，整片露出；北、东校区照此递推，互不影响 | 2.7s（两段） |

- 云层**只覆盖 3D 页**，2D 页不受任何影响。
- 云团由确定性伪随机（种子 `20261028`）生成 3~4 层同心圆，保证每次渲染同一片云、导出可复现。
- 「一片云 = 一个地标」的对应关系写在顶卡（12 格，南 / 北 / 东 分组计数）。

### 10.4 「打开后与真实 3D 地图无差别」如何保证 + 怎么验

1. **结构上**：云层是覆盖在 `#m3map` 之上的纯覆盖物（`mask` 打洞），孔洞内**不画任何替代底图**；
   校区 4/4 时该校区**直接不再生成云**，所以「散完」与「从未有云」是同一份渲染结果。

### B. Token 实测校准

`design/tokens/tokens.json` 此前停留在 v1.0 旧色板（`primary #146C5A` / `background #FBFDFC`），
与原型 v1.6 实际渲染（`--primary #00634D` / `--bg #F8F7F2`）**不一致**，导致检查器用假数据跑出全 PASS。
改由 `.cache/gen-tokens.py` 从原型 `:root` 实测提取后：

| 项目 | 旧值 | 实测后 | 说明 |
|---|---|---|---|
| `color.brand.primary` | `#146C5A` | `#00634D` | 与原型 `--primary` 一致 |
| `color.surface.background` | `#FBFDFC` | `#F8F7F2` | 与原型 `--bg` 一致 |
| `color.surface.onSurfaceVariant` | `#404A46` | `#5D6962` | 实测原 `#66716A` 在浅绿背景上仅 4.26，**未达 AA**，加深一档至 4.81 |
| `color.semantic.rewardGold` | `#C8A34A` | `#B58B45` | 与原型 `--gold` 一致 |

`semantic.onRewardGold` 在检查器里仍报 ✗（3.11，阈值按正文 4.5）。**实际该配对只用于 `.done .medal` 的奖章图标**，
非文本元素阈值为 3.0 —— 3.11 达标。属检查器按正文判定的误报，已在原型 CSS 内联注明，不在 UI 层改动。
