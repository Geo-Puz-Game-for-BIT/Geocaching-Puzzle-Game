## 1. 主线（15 步，正常路径）

| # | 玩家动作 | 页面 | 系统响应 | 数据变化 |
|---|---|---|---|---|
| ① | 打开 App | 启动页 | 读本地登录态，静默续登；无登录态则展示登录（登录方式**候选**） | `User` 恢复 |
| ② | 首次进入授予定位 | 系统弹窗 | 请求 `ACCESS_FINE_LOCATION`；拒绝则进 F1 | 权限态写入 |
| ③ | 看地图找地标 | P01 探索首页 | 定位 → 拉取当前校区 4 个地标 → 画 Marker + 推荐卡片 | `Landmark` 列表 |
| ④ | 切校区（可选） | P01 | 顶部切北 / 南 / 东，各显示 `n/4`；**三片区同构，都可看** | — |
| ⑤ | 点卡片看详情 | P02 详情 | 展示介绍、实时距离、定位状态、拍照任务 | `Task` 绑定 |
| ⑥ | 点「前往拍照」 | P03 相机 | 请相机权限 → 取景预览 + 构图辅助（人物与地标同框） | `Checkin` 建立（`requestId` 生成） |
| ⑦ | **按下快门** | P03 `preview` | **进入拍后预览**，照片还没发出去 | 照片存本地 |
| ⑧ | **重拍 / 确认提交** | P03 `preview` | 点重拍回到取景（不留记录）；点确认提交才真正上传 | `Checkin.state=PENDING` |
| ⑨ | （服务端）校验 | — | 到达地标附近 + 定位可用 + 照片现场拍摄（**门槛为候选，服务端定**） | `SUCCESS` / `FAILED` / 处理中 |
| ⑩ | 看结果 | P04 结果 | 成功：碎片归位、进度更新、「查看拼图」；处理中 / 待确认：**明确没有结果** | `Module.tiles` +1（仅成功时） |
| ⑪ | 进片区拼图 | P05 片区 2×2 | 四格：刚打的这一格亮起，其余按演示脚本 | `tiles.owned` |
| ⑫ | 系统判断片区集齐 | P05 片区 2×2 | `4/4` → 播放拼合动画（**自动归位，不需要拖**） | `Module.completed` |
| ⑬ | 拿片区奖励 | P05 片区 2×2 | 「成就 · 拼合<片区名>」+ 地图进度 `n / 3` | `achievements` +1 |
| ⑭ | 回地图总览 | P05 `overview` | 三片区：`MP-A 已合成`、`MP-B 1/4`、`MP-C 0/4`，已收 **5 / 12** | `Map.completedModules=1` |
| ⑮ | 三片区都齐 → 成图 | P05 `mapdone` | `12/12` 金色 + 「成就 · 校园地图完成」 | `Map.completed=true` |

**关键时序**：⑧ 确认提交是唯一不可逆动作，必须"**先落本地 + 生成幂等 requestId，再上传**"。
任何失败都能用**同一条请求**重试，不允许出现"拍了照、网断了、照片没了"。

**两级奖励**：⑫⑬ 是**片区级**（4 块 → 1 个模块），⑭⑮ 是**地图级**（3 模块 → 1 张图）。
演示走通 ①–⑬（南校区整条链路）；⑭⑮ 用预置数据演示（`MP-B` / `MP-C` 的打卡界面同样可看，与南同构）。

## 2. 六页之间的跳转关系

```
            ┌──────────── 返回 ────────────┐
            ↓                              │
P01 探索 ──点卡片──> P02 详情 ──前往拍照──> P03 相机
                                            │
                        取景 ──快门──> 拍后预览 ──重拍──> 取景
                                            │确认提交
                                            ↓
                                      P03 提交中 ──> P04 结果
                                                      │  ├ 成功 ──> P05 片区 2×2
                                                      │  ├ 处理中 / 待确认 ──┐
                                                      │  └ 未成功 ──> 留在 P03（重拍/重试）
                                                      │                     ↑
                                            P06 我的记录 ──「1 条打卡还在确认」──┘
   ↑                                                  │查看拼图
   │                                                  ↓
   └──── 去地图继续打卡 ──── P05 片区 2×2 ──返回──> P05 地图总览（3 片区）
                                  ↑                            │
                                  └──────── 点片区进来看 2×2 ───┘
```

- **P05 是同一页的两级视图**：默认落在「地图总览」，点任一片区进入该片区 2×2；片区页返回键回总览，总览返回键回 P01。
- **返回键行为**：P03 → P02（保留照片）；P04 成功 → 不可回退到 P03（照片已消耗），只能去 P05 或回 P01；
  P05 片区 → P05 总览 → P01（进度全程保留）。
- **结果未知的出口**：P04 处理中 / 待确认 → 可去 P06 **「1 条打卡还在确认」** 回到同一条请求；
  照片在 P06 里始终可见，删除照片不影响已得碎片。
- **深链**：`gt://landmark/LM-001` 直达 P02；`gt://puzzle/MP-A` 直达该片区 2×2；`gt://map` 直达总览；
  `gt://checkin/<requestId>` 直达某条打卡的结果页（幂等恢复用）。
- **不做**：页面间共享转场动画之外的花哨动效；不做侧滑抽屉、不做多 Tab 嵌套。

## 3. 状态机（任务 / 打卡 / 拼图 / 地图）

```
任务：未开始 ──进入 P02──> 进行中 ──确认提交──> 待确认 ──服务端通过──> 成功
                                              │
                                              ├──未通过──> 未成功 ──重拍/重试──> 进行中
                                              └──无结论──> 处理中 ──查询（幂等）──> 待确认

打卡：DRAFT ──确认提交──> PENDING ──成功──> SUCCESS
                            │
                            ├──网络失败──> DRAFT（照片保留，用同一 requestId 重试）
                            ├──校验失败──> FAILED（附 failReason，可重拍）
                            └──无结论──> CONFIRMING（不加奖；P06 可找回）

模块（片区）：0/4 ──每次打卡成功──> n/4 ──n=4──> 已合成（自动归位，无拖拽）
                                                     │
                                                     └── 集齐后可"回顾拼合过程"（次级入口）

地图：0/3 ──合成一个模块──> 1/3 ──> 2/3 ──> 3/3（完整地图 + 终极成就）
```

**幂等规则**：`requestId` 在确认提交前生成，重试与状态查询都带它。
服务端对同一 `requestId` 只记一次 —— **不重复提交、不重复发放碎片**。
**不发奖规则**：`PENDING / CONFIRMING` 期间一律不发碎片、不显示成功。

`failReason` 与界面文案的映射见 `docs/scope.md §4`，文案正文见 `design/copy/文案.md`。

## 4. 失败恢复（每条都要有出口）

| 编号 | 触发 | 玩家看到什么 | 玩家能做什么 | 落点 |
|---|---|---|---|---|
| F1 | 拒绝定位权限 | 顶部横幅：「需要位置权限才能找到附近地标」 | 「去设置」→ 授权后自动重试 | P01 |
| F2 | 拒绝相机权限 | 全屏空态：「需要相机权限才能拍照打卡」 | 「去设置」/「返回详情」 | P03 |
| F3 | 定位不佳 | 「定位还不够稳」，说明是信号问题不是玩家问题 | 「等定位稳定」+ 自动重试 | P01 / P03 |
| F4 | 不在地标附近 | 「还没到地标附近」+ 实时距离 | 走近后按钮自动可用（**不显示固定米数圈**） | P03 |
| F5 | 网络中断 | 「网络中断，暂时拿不到数据」 | 恢复网络后重试；**不承诺离线补交** | P01 / P02 / P03 |
| F6 | 提交失败 | 「没提交成功，碎片还没有发放」 | **照片保留**，用同一条请求重试，不重新拍 | P03 / P04 |
| F7 | 照片不可用 | 「这张照片用不了」+ 拍摄时只检测清晰人脸，不比对身份 | 一键重拍 | P03 / P04 |
| F8 | 片区内未集齐 | 「还差 N 块：<地标名>」+ 4 个地标打卡状态清单 | 回 P01，或点清单里的地标 | P05 片区 |
| F9 | 重复打卡 | 「该地标已完成，不会重复发放碎片」 | 「查看拼图」→ 该片区 2×2 | P02 / P03 |

**提交状态四态**：未发送 →（提交）→ 处理中 → 明确失败（有出口）/ 结果未知（保留原尝试、
幂等查询恢复，不显示确定失败、不放开重拍、不提前授奖）。详细口径见 `scope.md §4 v1.8`。
| F10 | 冷启动加载 | 骨架屏 ≤3s | 超时给「重新加载」 | P01 / P02 / P05 |
| **F11** | **结果未知** | 「服务端正在确认」→「结果待确认」；明说这一步没有结果 | 等；或去 P06「1 条打卡还在确认」回到该条 | P04 / P06 |
| ~~旧 F11~~ | ~~片区未开放~~ | **v1.3 删除**：北 / 东与南同构，随时可看 | — | — |

原则：**没有死路**。每个异常态至少一个主行动 + 一个退路（返回）。
**不做每日重置**：已完成的地标就是「已完成」，不写「今天打过了，明天再来」。
