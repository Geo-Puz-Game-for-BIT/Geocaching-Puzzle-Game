## 0. 写文案的规则

### 0.1 四条硬规则

1. **先说现象，再说动作**：`还差一点距离` → `走到地标跟前`，不写 `打卡失败(-1)`。
2. **人话动词，不用系统词**：提交 / 上传 / 校验 → 拍一张 / 发出去 / 算不算数。
3. **不吓人、不甩锅**：`定位还不够稳` 而不是 `GPS 异常，请检查设备`。
4. 单行不超过 18 个汉字（412dp 宽），按钮不超过 6 个字。

### 0.2 候选参数不许写死（v1.3 新增）

以下四项**未定案**，界面上**禁止**出现确定数值或确定性表述：

| 候选项 | 不能写 | 应该写 |
|---|---|---|
| 打卡半径 | 30 米内 / 需在 30 米内提交 | 需要到达地标附近 |
| 定位精度 | 精度需优于 20 米 / accuracy ≤ 20m | 定位要能用（实时定位误差作为技术观察展示，不写成门槛） |
| 照片时效 | 提交前 5 分钟内拍摄 | 照片需现场拍摄 |
| 登录方式 | （界面不承诺具体方式） | — |

统一兜底句：**「具体判定门槛以服务端规则为准。」**

> 定位误差（例：现场约 ±30 m）是**技术观察**，用来解释为什么定位不稳，
> **不等于打卡半径**。地图与相机页**都不画**固定的可打卡圆圈。

### 0.3 术语表（全项目统一，不许换说法）

| 概念 | 统一叫法 | 不要写 |
|---|---|---|
| 地标 | 地标 | 点位、POI、景点 |
| 任务 | 任务 | 关卡、活动 |
| 打卡 | 打卡 | 签到、check-in、上传 |
| 碎片 | 碎片 | 图块、piece、fragment |
| 拼图 | 拼图 | 合成图、puzzle |
| 一个 2×2 组合 | 片区（例：南校区） | 模块、module、关卡 |
| 三个片区合成物 | 校园地图 | 全图、总图、大地图 |
| 一块碎片 | 碎片（= 一个地标的一张打卡照） | 图块、piece、切片 |
| 偏差 | 定位误差 ±N 米 | 误差值、GPS 信号弱 |
| 未拿到结论 | 处理中 / 结果待确认 | 加载中、未知错误 |

## 8. 语气与长度自检

- 全篇不出现：`失败`、`错误`、`异常`、`ERROR`、`400/500`、`null`。
- 所有按钮以动词开头：查看、去、重拍、重试、走近、返回。
- 同义不一致检查：`重试/重来/再试` → 统一 **重试**；`返回/回退/退出` → 统一 **返回**。
- 数字与单位之间留空格：`68 m`、`±6 m`、`30 米内`（正文用「米」，数据浮层用「m」）。
- **不写每日重置**：不出现「今天」「明天」「每日」。
- **候选参数不写死**：不出现 30 米半径、20 米精度、5 分钟时效的具体数值（见 §0.2）。
- **不提前宣布成功**：处理中与结果待确认两态不得出现「成功」「已获得」。
