## 五、下一步计划（CameraX 链路优先，可独立于照片核验决策推进）

评审第 4 点：**CameraX 预览/拍照/重拍 → 私有文件 → Room 草稿 → 失败保留和恢复**，可以先于照片内容核验决策推进。

### 5.1 本链路（C 可独立推进）
1. `CAMERA` 权限声明 + 运行时申请。
2. CameraX `Preview` + `ImageCapture` 接入 `CameraScreen`（替换「模拟拍照」）。
3. 拍照后写入应用私有目录，生成 `LocalPhotoRef`（路径/mime/size），落 `CheckInDraft`。
4. 重拍：覆盖/清理旧草稿文件；取消：清理草稿。
5. 提交失败保留草稿与照片，下次进入可恢复（`UploadState.FAILED`）。

### 5.2 跨组协作边界（先统一调用边界，再实现）
| 对象 | 协作内容 |
|---|---|
| **B（架构/地图）** | 统一客户端调用边界：打卡成功回调如何通知「标记 landmark 完成」并驱动拼图点亮 |
| **D（API/云端）** | 固定受审契约与幂等规则：`SubmitCheckInRequest` / `CheckInReceipt`，服务端成功才持久化奖励，删除照片不撤销奖励 |
| **A（产品/UX）** | 拍后预览、草稿入口交互规范 |

### 5.3 硬规则（已确认）
- 只有服务端成功才持久化奖励（首次 +1）。
- 删除照片不撤销已获得的奖励。
- EXIF、照片核验、身份/重开一轮：提供方案，不自行冻结。
