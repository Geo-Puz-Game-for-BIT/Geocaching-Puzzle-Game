## 2. 当前揭示规则

客户端现在把“揭示范围”和“打卡范围”分开：

- 每个地标的打卡范围使用上表尺寸，用于开放拍照、重拍和提交。
- 揭示范围由打卡范围向外增加 **25 米边距**：圆形半径加 25 米；矩形四个方向各增加 25 米。
- 可靠定位进入任一揭示范围后，地标显示并保持显示；走远不会重新隐藏。
- 北湖以三个揭示锚点分别判断，任一锚点命中即可显示北湖。
- 揭示不授予碎片、不改变打卡资格；只有当前位置进入原始打卡范围且定位满足 30 米/5 秒门控，才允许拍照和提交。
- 精度超过战争迷雾探索阈值的样本不会产生可靠揭示；临时视野仍与永久探索分开。

25 米是当前实现的保守初值：对于半径 56 米的小地标，揭示半径为 81 米；对于大范围地标只多出 25 米，避免“靠近”范围大到失去隐藏感。后续可根据真机步行反馈统一调整边距，但不应让揭示范围反过来替代打卡范围。

## 4. 验收建议

1. 先用小范围地标验证：在打卡边界外、揭示边界内移动，地标应显示但拍照按钮仍禁用。
2. 进入原始打卡范围并保持精度 ≤30 米、位置样本 ≤5 秒，拍照入口才启用。
3. 北湖分别走到三个锚点附近，确认同一个北湖地标只显示一次；走到湖心或水面附近不应被视为安全拍摄站位。
4. 低精度位置只能显示临时视野，不能新增永久探索或自动揭示。
5. 云端迁移完成后，`GET /api/v1/landmarks` 应返回新的 `point`、`checkInArea` 和北湖 `revealPoints`；迁移前的旧坐标不能作为联机验收结果。

## 5. 后续隐藏藏点构思（本次不实现）

未来可以把隐藏藏点建模为独立 `hiddenSpot` 资源：它有自己的小揭示范围、是否需要完成整片地图的解锁条件、独立奖励和可见性状态。它不应复用正式地标的碎片 ID，也不应在当前 12 个地标 API 中伪装成普通地标。本次只保留正式地标的 `revealPoints` 能力，不加入隐藏藏点数据。
